Lesson 7 · about 30 minutes

Add the safe Node CLI

Slice 6 gives the verified browser-compatible TypeScript core one local filesystem entry point. Learn to keep the wrapper thin, reject unsafe path situations, publish output only after verification, and test the real process boundary.

Your tangible win: understand the CLI as seven small blocks, then connect them yourself in the required .mjs wrapper and subprocess test without receiving the finished script.

1. This slice is a boundary around TypeScript

The reusable implementation remains the TypeScript code under src/colmap/. The CLI is intentionally a Node ESM .mjs file because its only job is filesystem and process interaction. It imports the compiled public core, never the TypeScript source. 

scripts/colmap-round-trip.mjs
  → imports ../dist/colmap/index.js
  → calls roundTripRecorderZip

src/colmap/
  ✗ no node:fs
  ✗ no process.argv
  ✗ no filesystem paths

This direction proves that package consumers can use the built public entry. Importing ../src/colmap/round-trip.ts would test a private development shortcut and could hide a broken build or export.

Arguments

Require exactly one input path and one output path.

Path policy

Resolve paths and reject unsafe filesystem states.

Core call

Read bytes and ask the compiled orchestrator to verify them.

Publication

Write a temporary sibling and rename only after success.

Summary

Print the already-derived typed summary and final path.

Failure

Clean up, report concisely, and exit non-zero.

2. Block A — parse exactly two user arguments

Node exposes command-line values through process.argv. The first item is the Node executable and the second is the script; the CLI's user arguments begin at index two. 

process.argv
├─ [0] Node executable
├─ [1] CLI script
├─ [2] input ZIP
└─ [3] output ZIP

Require the sliced array to have length exactly two. Zero, one, or three user arguments all fail with a short usage line. Do not add optional flags, defaults, interactive prompts, or a command-line framework; Slice 6 has one fixed invocation.

Keep paths as separate argument-array elements. A path containing spaces is still one argument when the shell invokes the script correctly; the CLI should not split it again.

3. Block B — resolve and check filesystem policy

Use Node's path.resolve to turn both arguments into absolute paths. From then on, diagnostics, comparisons, temporary-file placement, and the printed output path use those resolved values.

Check Required behavior
Input and output resolve identically Fail before reading or writing.
Input is missing or not a file Fail with no output.
Input cannot be read Let the read failure remain visible.
Output parent is missing or not a directory Fail; do not create directories.
Final output already exists Fail; do not overwrite it.

When checking absence, distinguish ENOENT from every other filesystem error. “Permission denied” does not mean “the path is free.” Catch only the expected missing-path code and rethrow other failures.

Never delete the output merely because it exists. It belongs to the user. The contract says to fail, not to make the requested state true by removing something.

4. Block C — cross the byte boundary once

Read the entire input ZIP with the promise-based node:fs/promises API, then pass those bytes directly to roundTripRecorderZip. Node documents that Buffer extends Uint8Array, so the filesystem result satisfies the browser core's byte-oriented input without converting ZIP data to text. 

filesystem bytes
  → roundTripRecorderZip(bytes)
  → verified result containing outputZipBytes and summary

Do not open zip.js, decode COLMAP text, construct a model, or repeat any verification inside the CLI. The orchestrator already performs the entire read/serialize/reopen/compare flow. The CLI trusts only a fulfilled orchestrator promise.

5. Block D — treat output publication as a transaction

A final filename communicates “this operation succeeded.” Writing directly to that path would expose a partial ZIP if the write stops midway. Instead, create a unique temporary filename in the output's existing parent directory.

  1. Finish all in-memory round-trip verification first.
  2. Choose a unique temporary sibling of the final output.
  3. Write the verified Uint8Array to that temporary path.
  4. Rename the temporary file to the final path.
  5. Only then print the successful output location.
output parent/
├─ .result.zip.<unique>.tmp   ← incomplete/private
└─ result.zip                 ← appears only after success

Keep the temporary file beside the output, not in a global temporary directory. A sibling rename stays within the same filesystem and is the publication step required by the accepted plan. A standard-library unique value such as randomUUID(), plus exclusive creation, is sufficient; no temporary-file package is needed.

Write with an exclusive-creation flag so an extremely unlikely temporary name collision fails instead of overwriting somebody else's file. The final output existence check is still separate because the final path must never be intentionally replaced.

6. Block E — cleanup must not hide the real failure

Track the temporary path before writing it. If writing, renaming, or any later step fails, attempt to remove only that known temporary file. Do not remove the input or final output. 

try
  write temporary sibling
  rename temporary → final
catch original failure
  attempt temporary cleanup
  rethrow original failure

Cleanup is best effort. A cleanup error should not replace the original parsing, verification, or write failure, because that would report the wrong cause. This is the same control-flow lesson as avoiding a return inside finally: lifecycle code must not erase the operation's real result.

Once rename succeeds, the temporary path no longer exists and the final path is valid output. Do not run failure cleanup against the final path.

7. Block F — print values from the returned summary

The CLI formats presentation; it does not calculate domain values. Read counts, intrinsics, and image ID 1's world-to-camera pose from the returned summary. Print at least the exact information below after the final rename succeeds. 

Images: <count>
Camera <id>: PINHOLE <width>x<height> fx=<fx> fy=<fy> cx=<cx> cy=<cy>
Image 1 world-to-camera qvec: [qw, qx, qy, qz]
Image 1 world-to-camera tvec: [tx, ty, tz]
Output ZIP: <resolved path>

Joining the tuple components with ", " is enough. Do not reformat, round, normalize, invert, or convert the pose. Slice 5 already selected the record whose ID is exactly 1 and preserved the COLMAP world-to-camera convention.

8. Block G — one top-level failure boundary

Let the inner workflow throw naturally. One top-level catch prints a concise error to standard error and sets a non-zero status. Node's process documentation recommends process.exitCode when the process can finish naturally; immediate process.exit() can truncate pending standard-output or standard-error writes. 

top-level success
  → final output exists
  → summary on stdout
  → natural exit 0

top-level failure
  → no final output created
  → concise error on stderr
  → process.exitCode = 1

Expected ColmapError values already contain useful context. Filesystem errors have messages and codes. The CLI does not need a new error hierarchy or to convert every unexpected programmer error into a misleading COLMAP failure.

9. Test the process, not an extracted imitation

The required scripts/colmap-round-trip.test.mjs is a subprocess test. Build the package first, then launch the actual CLI with the current Node executable and an argument array. Node's spawnSync is adequate for a small CLI test because it returns status, stdout, and stderr together. 

process.execPath
  + [absolute CLI script, input path, output path]
  + shell disabled
  → status, stdout, stderr

Passing an argument array instead of constructing a shell command avoids quoting bugs and treats spaces or shell characters in paths as data. A shell is unnecessary here.

Create each test's files under a unique operating-system temporary directory. The test may hand-build the same small recorder ZIP shape used by earlier slices; it must not use a tracked real Task 1 fixture in Slice 6.

10. Minimum subprocess evidence

  1. Zero, one, and three user arguments fail with non-zero status.
  2. Resolved identical input and output paths fail.
  3. A missing or non-file input fails.
  4. A missing output parent fails without creating it.
  5. An existing output fails and its original bytes remain unchanged.
  6. An invalid recorder archive produces no final output.
  7. Failure leaves no temporary sibling behind.
  8. A valid synthetic input exits zero and creates one output ZIP.
  9. The original input bytes remain unchanged.
  10. The output reopens through the compiled public core.
  11. Stdout contains all required summary lines and resolved output path.
  12. The ID-1 pose is printed even when image ID 1 is not first.
  13. Missing image ID 1 fails with no final output.

Avoid asserting an entire failure message character-for-character. Test the non-zero status, relevant error fragment, absence of final output, preservation of existing files, and temporary cleanup. Success output has a required presentation contract, so its important lines deserve direct assertions.

11. Build and package-script order matter

The wrapper imports dist/colmap/index.js, so stale or absent build output must not accidentally pass. Make the colmap:roundtrip package command perform or require the build before launching the wrapper, and make the subprocess suite run after a package build. 

package build
  → dist/colmap/index.js
  → CLI subprocess test
  → local colmap:roundtrip invocation

Include scripts/ in the relevant formatting and test scopes. The existing Vitest pattern already includes scripts/**/*.test.mjs; confirm the complete package gate actually executes it rather than assuming that a colocated test was discovered.

12. Keep later slices out

Slice 6 does not replay the real Task 1 archives, start LichtFeld, create a web page, integrate AppFramework, add progress reporting, accept directories, overwrite output, or introduce configurable flags. It proves one local command around the already accepted public core.
