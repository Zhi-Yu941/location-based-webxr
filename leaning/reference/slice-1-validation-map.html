Model, validation, and boundary map

A compact map of responsibilities and rules. It is a checklist, not a finished implementation.

Rule matrix

Area Accept Reject
IDs Positive safe integers; sparse and out of order Zero, negative, fractional, unsafe, duplicate
Camera count Exactly one PINHOLE Zero, many, unsupported model
Dimensions Positive safe integers Zero, negative, fractional, unsafe
Intrinsics Finite; fx and fy positive NaN, infinity, non-positive focal length
Images At least one; unique ID/name; existing camera reference Duplicate, missing reference, unsafe filename
Pose Finite tuple values; unit norm within 1e-6 NaN, infinity, non-unit quaternion
Points Zero or more; finite XYZ; finite non-negative error Duplicate ID, non-finite XYZ/error, negative error
RGB Integer channels from 0 through 255 Fractional channels or values outside the range
Observations/tracks Empty arrays Any populated array, as unsupported profile

Filename rule

Require a non-empty single filename. Reject ., .., slashes, backslashes, spaces, tabs, quotes, NUL, and control characters. Do not require a particular extension or frame-NNNNNN pattern. Comparison is case-sensitive.

Mutation firewall

  • Do not round or clamp numbers.
  • Do not normalize or sign-flip quaternions.
  • Do not reorder, renumber, insert, or remove records.
  • Do not alter filenames or pose meaning.
  • On success, return or confirm the same complete model.
  • On failure, throw; never return a partially accepted model.

Package gate

Formatting, lint, production typecheck, test typecheck, build, and unit tests must all pass. Node imports may exist in build/test configuration; they must not enter the production src/colmap dependency graph.
