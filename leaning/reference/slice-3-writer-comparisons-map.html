Canonical writer and comparison map

The exact output rules and the boundary between semantic equivalence and exact no-op preservation.

Writer pipeline

typed model→ validate all→ three byte arrays
  • Validate the complete model before generating output.
  • Preserve array order, IDs, references, names, and quaternion sign.
  • Use exact headers, one ASCII space, LF, and a final LF.
  • Use round-trip-safe base-10 strings; never fixed decimals.
  • Emit both 0 and -0 as 0.
  • Emit one empty observation line after every image pose.
  • Recompute counts and produce identical bytes on repeated calls.

Two predicates

Property Semantic equality Exact preservation
Counts, order, IDs, names, references Exact Exact
Dimensions and RGB Exact Exact
Approved floating fields Absolute/relative tolerance ===, with zero signs equal
Quaternion q and -q equivalent Original component sign required
Source comments/whitespace Not model data Not model data

Approved floating predicate

abs(a - b) <=
  max(1e-12, 1e-12 * max(abs(a), abs(b)))

Apply it only to intrinsics, quaternion/translation components, point XYZ, and point error. Never apply it to IDs, dimensions, RGB, names, references, counts, or order.

Quaternion decision

  1. Both quaternions have already passed model validation.
  2. Compute their dot product.
  3. If the dot is negative, compare the right quaternion after sign reversal.
  4. Compare aligned components with the semantic float predicate.

Semantic comparison accepts a pure sign flip. Exact preservation reports that same case as quaternion-sign. A genuinely different rotation reports quaternion-orientation.

Deterministic failure order

  1. Camera collection, records, then fields.
  2. Image collection, records, then fields.
  3. Point collection, records, then fields.
  4. Return immediately on the first difference.

Paths use stable zero-based notation such as images[2].pose.qvec[0]. Return { equal: true } only after every required field passes.

Do not add

No ZIP handling, filesystem access, arbitrary deep-equality library, configurable tolerance system, accumulated diff report, pose conversion, or comparison of original text formatting.

Study with Lesson 4: write and compare without hiding changes. Primary JavaScript references: equality and sameness and TypeScript discriminated unions.
