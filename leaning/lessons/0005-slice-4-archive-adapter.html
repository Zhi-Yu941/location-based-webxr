Lesson 5 · about 30 minutes

Build one safe archive adapter

Slice 4 promotes the ZIP feasibility idea into a real boundary. Learn how to inventory untrusted entries, reject ambiguous paths, resolve image assets exactly, and copy everything while changing only three payloads.

Your tangible win: describe and test the four adapter blocks, then connect them yourself without receiving a finished production implementation.

1. The spike proved mechanics; Slice 4 adds policy

Your Slice 0A test already proved that zip.js can open a Uint8Array, expose directory records, return decompressed file bytes, and write another readable archive. Reuse that mental model. Slice 4 adds the rules that make those mechanics safe for recorder data.

Open

Read every entry into one validated in-memory inventory.

Check profile

Reject unsafe names, collisions, missing text, and binary models.

Resolve images

Find each model image at one exact case-sensitive path.

Copy

Re-add every entry and substitute exactly three text payloads.

The adapter does not parse COLMAP, serialize models, calculate poses, summarize datasets, access the filesystem, or know recorder metadata formats. Those responsibilities already have or will get another owner.

2. Read the types as promises between blocks

ArchiveEntry is the complete snapshot: stored path, file or directory kind, and decompressed bytes. Its kind field is a discriminant, so TypeScript can narrow a file before code treats its bytes as a replaceable payload.

Type Promise it makes
ArchiveEntry One validated entry whose original path was not rewritten.
ArchiveFileEntry The entry is known to be a file, not merely cast as one.
OpenedRecorderArchive All entries passed policy and all three text payloads exist.
RecorderZipAdapter One component exclusively owns ZIP reading and reconstruction.

readonly protects TypeScript callers from accidental assignment; it does not validate bytes arriving from a ZIP. Runtime evidence must be established inside open before returning the stronger archive type.

3. Block A — start from an independent synthetic contract

Hand-build one valid recorder-like ZIP in the test. Include the three sparse texts, explicit directories, referenced and unreferenced images, actions/, session.json, an unknown binary file, and at least one empty file. Keep an independent expected inventory so a broken reader cannot define both sides of its own assertion. 

declared expected entries
        ↓ build ZIP
raw ZIP bytes
        ↓ adapter.open
validated inventory
        ↓ compare
declared expected entries

Then derive each negative fixture from the valid fixture by changing one fact. One failing reason per test makes the policy reviewable and prevents an earlier failure from hiding the behavior you meant to test.

4. Block B — open with an all-or-nothing reader lifetime

The read loop resembles the spike: construct a ZipReader, get every entry, derive the kind from zip.js, and request data only for files. Directory snapshots retain empty bytes because their existence and kind still matter. 

create reader
try {
  get all entries
  validate and snapshot every entry
  validate complete recorder profile
} finally {
  close reader
}
return complete opened archive

Keep the return after finally. A return inside finally would suppress an earlier path, decompression, or profile failure and could return a partial archive. Do not publish the inventory until every entry and profile rule has passed.

5. Block C — validate the stored path; never repair it

“Normalized path” in this contract means the original ZIP filename after validation. It does not mean transformed text. Do not replace backslashes, collapse segments, URL-decode, Unicode-normalize, or run the value through filesystem path helpers.

  1. Check that the stored string is non-empty and relative.
  2. Check kind and shape: files have no trailing slash; directories have exactly one.
  3. Reject backslashes, drive prefixes, control characters, and NUL.
  4. Split the permitted non-trailing portion on /.
  5. Reject empty, ., and .. segments.
  6. Return the same string, unchanged, only after every check passes.
Stored entry Decision
sparse/0/cameras.txt, file Accept unchanged
images/, directory Accept unchanged
/images/a.jpg Reject absolute path
C:/images/a.jpg Reject drive-qualified path
images\a.jpg Reject non-POSIX separator
images//a.jpg or images/../a.jpg Reject invalid segment
images/, file Reject kind/path mismatch

6. Block D — detect aliases before building lookups

Two ZIP records must not become one file when materialized on Windows. A Map from an ASCII-folded key to the first original path can detect both exact duplicates and case-only collisions while keeping the original spelling for a useful error. 

ASCII fold only:
path.replace(/[A-Z]/g, letter => letter.toLowerCase())

"images/A.jpg" and "images/a.jpg"
                ↓ same folded key
             reject archive

Ordinary toLowerCase() folds more than ASCII, so applying it to the whole path would enforce a broader rule than the accepted contract. Folding is only a collision check; never store or emit the folded string as the entry path.

7. Block E — turn a runtime inventory into the required profile

A TypeScript union such as SparseTextPath disappears at runtime. You still need a small runtime list of the three exact paths to check the archive and build colmapText. 

required text paths:
- sparse/0/cameras.txt
- sparse/0/images.txt
- sparse/0/points3D.txt

forbidden model paths:
- sparse/0/cameras.bin
- sparse/0/images.bin
- sparse/0/points3D.bin

Require one file at every text path. Any missing member means a partial model and fails the whole open. Reject any forbidden binary path even when all three text files also exist; otherwise the output could carry two inconsistent COLMAP models.

Do not parse the three byte arrays here. The adapter proves that the files exist and returns their bytes; the text codec owns their syntax.

8. Block F — resolve model images by exact archive identity

Build an exact path index for file entries after duplicate checks have passed. For each ColmapImage, construct only images/<NAME> and request that exact key. Preserve model order in the returned result. 

model name: frame-000002.jpg
lookup key: images/frame-000002.jpg

Do not search by basename, suffix, ZIP order, or case-insensitive match. A missing exact file is a reference failure. An extra image that no model record references is valid and remains in the archive.

9. Block G — copy the inventory, not the typed model

copyWithReplacements receives the opened inventory and a record containing the three serializer payloads. Iterate over every inventory entry. Recreate directories explicitly; for a file, choose replacement bytes only when its exact path is one of the three sparse text paths. 

for every opened entry
  directory -> add explicit directory record
  selected file -> add replacement bytes
  other file -> add original decompressed bytes

close writer -> output Uint8Array

This is why the adapter keeps all entries. Reconstructing from the typed COLMAP model would silently lose actions, session data, unknown files, explicit directories, and unreferenced images.

10. Reopen the result and compare the right facts

The test must pass produced bytes back through open. A successful ZipWriter.close() only proves that bytes were returned, not that the adapter can read and validate them again.

Compare Ignore
Exact path set ZIP entry order
File/directory kind per path Compressed archive bytes
Replacement bytes at three paths Compression method or level
Original decompressed bytes everywhere else Timestamps, comments, and extra fields

Compare by path, not array position. This makes the test independent of entry order while still proving explicit directories, empty payloads, binary data, unknown files, and unreferenced images survived.

11. Errors belong to the shared boundary

Reuse ColmapError. Unsafe ZIP structure, duplicates, collisions, missing sparse texts, and binary coexistence use the archive kind with the relevant stored path. A model image that has no exact file uses reference and identifies the image name or model field. Do not add a second ZIP-specific error tree.

Expected bad input should reject the promise. The test should assert structured context rather than only a fragile full message. No partial OpenedRecorderArchive and no output bytes represent success after a failure.

12. Minimum evidence for Slice 4

  1. A valid synthetic recorder profile opens into the exact inventory.
  2. Each missing sparse text fails independently.
  3. Any matching sparse binary file fails, including coexistence.
  4. Absolute, drive, backslash, control, repeated, dot, and parent paths fail.
  5. File/directory path-shape mismatches fail.
  6. Exact duplicates and ASCII-case collisions fail.
  7. Referenced images resolve exactly and in model order.
  8. A missing referenced image fails; an unreferenced image remains valid.
  9. Output reopens with the same path and kind set.
  10. Exactly three payloads change to the supplied replacement bytes.
  11. Every untouched decompressed payload remains byte-identical.
  12. Formatting, lint, both typechecks, build, and unit tests pass.

13. Keep later slices out

Do not add readRecorderZip, writeRecorderZip, summary logic, round-trip model comparison, CLI paths, real fixtures, or AppFramework integration. Slice 5 will connect this internal adapter to the codec and public functions. Slice 4 only proves the archive boundary itself.
