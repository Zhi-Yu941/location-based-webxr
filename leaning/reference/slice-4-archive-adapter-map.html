Recorder archive-adapter map

One in-memory ZIP owner: validate identities, inventory bytes, resolve images, and copy with exactly three replacements.

Four operations

ZIP bytes→ validated inventory→ copied ZIP bytes
Block Responsibility
open Read all entries, validate paths/profile, expose three texts.
Path/profile checks Reject ambiguity; never repair or omit stored names.
resolveImages Find exact file key images/<NAME>.
copyWithReplacements Copy all entries; replace only three sparse text payloads.

Valid stored path

  • Non-empty relative POSIX path using / only.
  • No leading slash, drive prefix, UNC form, backslash, or control character.
  • No repeated slash or empty, ., or .. segment.
  • File: no trailing slash.
  • Directory: exactly one required trailing slash.
  • Return the original string unchanged after validation.

Collision rule

fold only ASCII A-Z for a lookup key
keep the original path as the stored identity
reject exact duplicates and case-only aliases

images/A.jpg and images/a.jpg collide for the Windows compatibility workflow. Folding is never an image-resolution or output-rewriting rule.

Required recorder profile

Image resolution

  1. Index only validated file entries by their exact original path.
  2. For each model image, form images/<NAME>.
  3. Look up that exact case-sensitive key.
  4. Return matches in model order; fail when one is absent.

Unreferenced image files remain valid opaque entries and must survive copying.

Copy-through oracle

  • Reopen emitted bytes through the adapter.
  • Compare path sets independent of entry order.
  • Compare file/directory kind at every path.
  • Compare supplied bytes at exactly the three replacement paths.
  • Compare original decompressed bytes at every other path.
  • Explicitly cover directories, empty files, binary data, and unknown files.

Do not add

No filesystem paths, Buffer, extraction, path repair, COLMAP parsing, serialization, public orchestration, summary, model comparison, CLI, real fixtures, or ZIP metadata guarantees.
