Recorder COLMAP text-reader map

The narrow parsing rules for the three recorder text payloads. This is a responsibility map, not a finished reader.

Pipeline

Uint8Array→ strict text→ typed model

Bytes → strict decoding → physical lines → exact tokens → private candidates → Slice 1 validator. Canonical writing and model comparisons begin in Slice 3.

Supported record shapes

File Data shape Recorder restriction
cameras.txt 8 tokens on one line Exactly one PINHOLE camera
images.txt 10-token pose line plus one physical observation line The observation line must be empty or ASCII whitespace
points3D.txt 8 tokens on one line No track tokens

Decode before parsing

  • Reject UTF-8 BOM bytes before decoding.
  • Decode with fatal UTF-8 so malformed bytes throw.
  • Reject NUL.
  • Accept LF and CRLF; reject a bare carriage return.
  • Accept an optional final line ending.
  • Keep physical line numbers for contextual errors.

Token grammar

UNSIGNED_INTEGER := 0 | [1-9][0-9]*
FLOAT := -?(0|[1-9][0-9]*)(\.[0-9]+)?([eE][+-]?[0-9]+)?

Match the whole token before calling Number. Therefore +1, .5, 1., 01, hexadecimal, NaN, and Infinity fail lexically instead of being partially or broadly converted.

Error ownership

Problem Kind Owner
Invalid UTF-8, arity, or numeric token syntax Codec
Non-empty observations or point tracks unsupported-profile Codec
Duplicate ID, invalid range, or non-unit quaternion validation Slice 1 validator
Image references an absent camera reference Slice 1 validator

Do not mix into Slice 2

Canonical writing, model comparisons, ZIP paths, image bytes, archive copying, image resolution, filesystem access, CLI behavior, LichtFeld, pose refinement, and general COLMAP observations/tracks remain outside the text reader.
