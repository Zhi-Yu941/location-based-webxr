1. The mental model: four byte boundaries

zip.js separates the ZIP container from each decompressed entry payload. For this experiment, both sides use Uint8Array, but they are not the same bytes.

ZIP bytes→ entry snapshots→ new ZIP bytes

Open archive bytesZipReader + Uint8ArrayReader
Extract one file payloadentry.getData(new Uint8ArrayWriter())
Add one file payloadzipWriter.add(path, new Uint8ArrayReader(bytes))

The test runner may be Node, but the code under experiment remains browser-compatible because it uses typed arrays, TextEncoder, and zip.js—not Buffer or the filesystem.

2. Create files and real directory records

A path prefix does not prove that an explicit directory entry exists. Add the directory itself with directory: true. Keep the trailing slash because the snapshot contract cares about the exact stored path. 

const encoder = new TextEncoder();
const zipWriter = new ZipWriter(new Uint8ArrayWriter());

await zipWriter.add("sparse/", undefined, { directory: true });
await zipWriter.add("sparse/0/", undefined, { directory: true });

await zipWriter.add(
  "sparse/0/cameras.txt",
  new Uint8ArrayReader(encoder.encode("original camera data")),
);

await zipWriter.add(
  "unknown/data.bin",
  new Uint8ArrayReader(new Uint8Array([0, 255, 1, 128])),
);

const zipBytes = await zipWriter.close();

Use recognizable text for most fixtures, arbitrary bytes for at least one file, and an actually empty file such as points3D.txt. An empty file and a directory both have zero payload bytes, so only kind distinguishes them.

Common trap: omitting close(). It finalizes the ZIP's central directory and returns the complete Uint8Array.

3. Inventory by narrowing the entry type

getEntries() returns both file and directory entries. The boolean entry.directory is a TypeScript discriminant. Branch on it before calling getData, because directory entries do not have a file payload to extract. 

type Snapshot = {
  path: string;
  kind: "file" | "directory";
  bytes: Uint8Array;
};

const zipReader = new ZipReader(new Uint8ArrayReader(zipBytes));

try {
  const entries = await zipReader.getEntries();
  const snapshot: Snapshot[] = [];

  for (const entry of entries) {
    if (entry.directory) {
      snapshot.push({
        path: entry.filename,
        kind: "directory",
        bytes: new Uint8Array(),
      });
    } else {
      snapshot.push({
        path: entry.filename,
        kind: "file",
        bytes: await entry.getData(new Uint8ArrayWriter()),
      });
    }
  }
} finally {
  await zipReader.close();
}

Notice that entry.filename is the archive path. Use forward slashes in ZIP paths. The zip.js API explicitly warns that backslashes are stored as literal filename characters and can be interpreted inconsistently.

4. Rebuild from the opened snapshot

This is the proof-producing step. The output must be derived from the inventory of the input. Only choose different bytes when the current path matches the replacement target. 

const replacementPath = "sparse/0/cameras.txt";
const replacementBytes = encoder.encode("replacement camera data");
const outputWriter = new ZipWriter(new Uint8ArrayWriter());

for (const item of inputSnapshot) {
  if (item.kind === "directory") {
    await outputWriter.add(item.path, undefined, { directory: true });
    continue;
  }

  const bytes =
    item.path === replacementPath ? replacementBytes : item.bytes;

  await outputWriter.add(item.path, new Uint8ArrayReader(bytes));
}

const outputZipBytes = await outputWriter.close();

Do not build a second hard-coded entry list. If the loop walks the opened snapshot, then unknown/data.bin and images/unreferenced.jpg survive without special-case knowledge. That is the property the later adapter needs.

5. Reopen first, then compare semantics

Run the same inventory helper over outputZipBytes. Build maps keyed by path so entry order cannot accidentally become part of the contract. 

const beforeByPath = new Map(
  inputSnapshot.map((item) => [item.path, item]),
);
const afterByPath = new Map(
  outputSnapshot.map((item) => [item.path, item]),
);

expect(new Set(afterByPath.keys())).toEqual(new Set(beforeByPath.keys()));

for (const [path, before] of beforeByPath) {
  const after = afterByPath.get(path);

  expect(after?.kind).toBe(before.kind);
  expect(after?.bytes).toEqual(
    path === replacementPath ? replacementBytes : before.bytes,
  );
}

Deep equality is essential for typed arrays. toBe would test object identity, not byte content. Also include direct, named assertions for the explicit directories, binary file, unknown file, unreferenced image, and empty file: those assertions make the intent obvious during review.

  4. Write a small inventory helper that always closes its reader.
